# Cyber Jungle

## 프로젝트 소개

Cyber Jungle은 Codex를 활용해 바이브 코딩 방식으로 제작한 연습 프로젝트입니다. 교육 과정 구성원이 같은 가상 캠퍼스에 접속해 실시간으로 만나고, 대화하고, 파티를 모집할 수 있는 2D 커뮤니티 서비스를 목표로 했습니다.

## 서비스 화면

### 로비

메인 진입 공간으로, 사용자가 처음 접속한 뒤 다른 공간으로 이동하기 전에 머무르는 공용 허브입니다.

![로비 화면](./docs/images/lobby.png)

### 농구 코트

사용자가 이동해서 진입할 수 있는 세부 공간 중 하나로, 로비와 구분된 별도 area 화면입니다.

![농구 코트 화면](./docs/images/basketball_court.png)

### 카페테리아

대화와 파티 모집이 가능한 공간으로, 다른 테마의 area가 어떻게 구성되는지 보여주는 예시 화면입니다.

![카페테리아 화면](./docs/images/cafeteria.png)

### 강의실

가상 캠퍼스 내 학습 공간 콘셉트를 반영한 area로, 사용자가 공간 단위로 이동하며 상호작용할 수 있음을 보여줍니다.

![강의실 화면](./docs/images/classroom.png)

## 기획 의도
- 정글 내에서 타 교육장, 타 교육과정 사람들과의 소통 부재를 경험
- 가볍게 즐길 수 있는 메타버스 환경에서 소통하는 경험을 통해 커뮤니케이션 활성화를 도모

## 주요 기능

- 사용자 정보를 입력하여 바로 입장할 수 있습니다.
- 같은 공간의 사용자 위치와 움직임이 실시간으로 동기화됩니다.
- 채팅을 통해 다른 사용자와 대화할 수 있습니다.
- 로비를 제외한 공간에서 파티를 만들고, 정해진 인원만큼 참여할 수 있습니다.
- 같은 area에 있는 사용자끼리 음성 연결을 시도할 수 있습니다.

## 담당 역할

이 프로젝트에서 저는 음성 커뮤니케이션 기능을 담당했습니다. 목표는 같은 장소(area)에 있는 사용자들끼리만 서로 음성으로 소통할 수 있도록 만들어, 공간 기반 커뮤니티 경험을 더 자연스럽게 만드는 것이었습니다.

- `M` 키를 눌러 마이크 입력을 켜고 끌 수 있도록 구성했습니다.
- `V` 키를 눌러 다른 사용자의 음성을 수신할지 여부를 제어할 수 있도록 구성했습니다.
- 같은 장소에 있는 사용자들 사이에서만 음성 연결을 시도하는 흐름을 구현해, 불필요한 전체 연결이 발생하지 않도록 설계했습니다.

이 기능을 통해 사용자가 단순히 채팅만 하는 것이 아니라, 같은 공간에 모인 사람들과 더 빠르고 자연스럽게 소통할 수 있는 환경을 만들고자 했습니다.

## 기술적 한계와 시도

구현 과정에서 가장 어려웠던 부분은 마이크 입력을 서버를 통해 다른 사용자에게 어떻게 전달해야 하는지 이해하는 것이었습니다. 브라우저에서 제공하는 마이크 접근 기능을 이용해 로컬 환경에서 입력을 다루는 것 자체는 비교적 수월했지만, 원격 사용자 간 음성 데이터를 안정적으로 주고받는 부분은 완성하지 못했습니다.

특히 JavaScript만으로도 구현이 가능하다는 이야기는 들었지만, 실제로는 음성 데이터가 어떤 경로로 전달되고 어떤 방식으로 연결이 성립되는지에 대한 이해가 부족해 구현을 끝까지 이어가지 못했습니다.

이 경험을 통해 브라우저의 마이크 접근과 실시간 통신은 별개의 문제라는 점을 체감했습니다. 이후에는 WebRTC 기반 음성 전송 구조와 시그널링 흐름, 그리고 사용자 간 음성 데이터 공유 방식 자체를 더 깊이 이해하는 것이 필요하다고 느꼈습니다.

## 실행 방법

직접 로컬에서 끝까지 실행하며 검증한 것은 아니지만, 현재 저장소에 포함된 스크립트와 설정 파일을 기준으로 보면 아래 방식으로 실행하는 구조입니다.

### 1. 패키지 설치

```bash
npm install
```

### 2. 개발 서버 실행

클라이언트와 서버를 함께 실행하려면 아래 명령어를 사용합니다.

```bash
npm run dev
```

`package.json` 기준으로 위 명령은 다음 두 작업을 함께 실행합니다.

- `dev:client`: Vite 클라이언트 실행
- `dev:server`: `server/index.js` 실행

### 3. 접속 주소

- 프론트엔드: `http://localhost:5173`
- 백엔드: `http://localhost:3001`

### 4. 환경 변수

`.env.example` 기준으로 확인되는 값은 아래와 같습니다.

```env
VITE_SERVER_URL=http://localhost:3001
CORS_ORIGIN=http://localhost:5173
```

프론트엔드가 백엔드와 정상적으로 통신하려면 위 값에 맞춰 로컬 환경을 구성해야 합니다.

### 5. Windows 배치 파일 실행

저장소에는 배치 파일도 포함되어 있어 Windows 환경에서는 아래 파일로 실행할 수 있습니다.

- `start-dev.bat`: 클라이언트와 서버를 함께 실행
- `start-client.bat`: 5173 포트에서 클라이언트 실행
- `start-server.bat`: 3001 포트에서 서버 실행

## 배포

이 프로젝트는 프론트엔드와 백엔드를 분리해서 배포하는 구조로 구성했습니다. 저장소에 포함된 설정 파일 기준으로 보면, 프론트엔드는 Vercel, 백엔드는 Render 환경을 기준으로 배포를 고려했습니다.

### 프론트엔드

프론트엔드는 Vercel 배포를 기준으로 구성했습니다. [vercel.json](C:\home\dolggul2\cyber_jungle\OpenAI_Project\vercel.json)에는 모든 경로 요청을 `index.html`로 연결하는 rewrite 설정이 포함되어 있어, React SPA가 새로고침이나 직접 URL 접근 시에도 정상적으로 동작하도록 맞췄습니다.

배포 시에는 `VITE_SERVER_URL` 환경 변수를 통해 백엔드 서버 주소를 연결해야 합니다.

### 백엔드

백엔드는 Render 배포를 기준으로 구성했습니다. [render.yaml](C:\home\dolggul2\cyber_jungle\OpenAI_Project\render.yaml) 기준으로 보면 Node 웹 서비스로 설정되어 있고, `npm install` 이후 `node server/index.js`를 실행하는 방식입니다.

이때 브라우저 통신을 위해 `CORS_ORIGIN` 환경 변수를 프론트엔드 배포 도메인에 맞게 설정해야 합니다.

### 서버 실행 환경

저장소에는 [Dockerfile](C:\home\dolggul2\cyber_jungle\OpenAI_Project\Dockerfile)도 포함되어 있어, 서버를 컨테이너 환경에서 실행할 수 있도록 준비했습니다. 이 설정에서는 Node 22 기반 이미지에서 의존성을 설치하고, `server/index.js`를 실행하도록 구성되어 있습니다.
